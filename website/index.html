    Rules first. The model last.

    Searching, tagging what a rule can match, sweeping old notifications, syncing finished tasks and writing the report are plain code. A model is called only for human mail that needs interpreting, and only after the rules have had their turn.

    1. Every run

      Sync tasks

      Finished Google Tasks archive their thread, if the tag says so.

    2. rules.json

      Rules

      Your Gmail queries, in order. First match wins; the message never reaches a model.

    3. Per tag

      Sweep

      Archive or mark read what is done: resolved alerts, yesterday's newsletters. Starred mail is left alone.

    4. Cheap model

      First pass

      What is left goes in batches of 25, as untrusted data, to a lightweight model.

    5. Stronger model

      Escalation

      Only low-confidence cases, with a bounded slice of the body, up to ten per run.

    6. Code again

      Validate, then write

      IDs, tags, task policy and dates are checked, the inbox is rechecked, tasks come first, then labels.

    Nothing moves without your say-so.

    Every command that would change your mailbox is a preview until you add --apply. The model proposes; plain code decides whether the proposal is even allowed.

    • Dry run by default

      Previews write the exact plan to state/plan.json; apply-plan --apply replays it without searching again.

    • Journalled, undoable

      Applied label changes go to a journal; triage.py undo reverts the last batches.

    • Validated before written

      Exactly the requested IDs, known tags, allowed tasks, real dates. Anything else and the batch is refused.

    • Unsure stays in the inbox

      No "FYI" fallback, no automatic archive. Unresolved mail is listed in summary.json and left for you.

    • Starred mail is protected

      Sweeps skip starred messages by default, through a guard you can edit.

    • Private by construction

      Mail stays in a local state/ folder only you can read. Logs record counts, never content, and mail text is treated as data, never as instructions.

    Board in three commands.

    The setup script installs what is missing with Homebrew, signs you in with only the Gmail-modify and Tasks scopes, then runs the tests and a read-only, model-free dry run. It never changes mail and never installs the schedule.

    1. Clone, then preview the setup.

      --dry-run prints every command before anything runs.

    2. Personalise your rules.

      The mail-setup skill reads at most 200 recent messages, read-only, and proposes sender rules for you to approve.

    3. Schedule it when the dry run looks right.

      schedule.py install runs weekdays, hourly, 08:00 to 19:00.

$ git clone https://github.com/mmornati/ai-email-assistant.git

    What it won't do.

    Said as plainly as what it does.

    • Gmail onlyThrough the Google Workspace CLI, with Google Tasks for the to-do side.
    • Polling, not pushEach run looks at a time window (7 days by default); there is no history cursor.
    • macOS for the scheduleThe schedule is a launchd calendar job; the Mac must be on and you logged in.
    • Confidence is not calibratedIt is what the model reports. Review real output before trusting unattended runs with important mail.
    • No silent cleanupThe starter rules archive and trash nothing. Every cleanup action is one you add.
    • Not affiliatedAn independent project; not endorsed by Google or GitHub.
